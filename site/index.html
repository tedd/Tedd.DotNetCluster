Architecture

How a release reaches a worker

/app

Publish a release

The CLI writes the published directory to TDFS and names its snapshot in one transaction. Workers mount that revision read-only.

sample-0

Place the replicas

Workers report their zone, installed images and capacity. The scheduler spreads replicas across eligible workers and DotNetPod runs each one in a Linux container.

/data

Keep the replica’s files

Persistent files belong to the deployment name and replica number. When a replacement takes over, TDFS grants its generation write access to those files.

Quick start

Run one replica.

Start with a Linux worker, Docker Engine, FUSE 3 and a TDFS volume. Build the CLI and sample with .NET 11, then set the storage credentials and local runtime image ID in the two configuration files.

Build and configure the sample
Bash Repository root
# With cluster.json and sample.json configured
mesh() { dotnet ./out/worker/Tedd.DotNetMesh.dll "$@"; }

mesh publish cluster.json sample.json ./out/sample
mesh apply cluster.json sample.json
mesh worker cluster.json

Keep the worker running. In another terminal, run dotnet ./out/worker/Tedd.DotNetMesh.dll status cluster.json to check placement and readiness.
